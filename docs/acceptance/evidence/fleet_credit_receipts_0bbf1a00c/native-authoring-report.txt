## What changed

- Replaced `with_for_update()` / `populate_existing()` with a real database CAS:
  - conditional `UPDATE` over the exact observed physical JSON value
  - distinguishes SQL `NULL` from JSON `null`
  - bounded reload/retry, fail-closed after contention
  - shared by `record_usage`, the verified-regression writer, and `reset_maturity`
- Borrowed-session handling now treats any active transaction or pending edit as caller-owned, including already-flushed edits:
  - uses an independent owned session when the engine can provide one
  - explicitly refuses when it cannot, without committing, rolling back, expiring, or flushing caller state
  - no longer borrows a caller transaction for receipt consumption
- Receipt + counter update remains transactional:
  - if the capability counter CAS cannot be applied, the receipt savepoint is rolled back
  - recovery can still apply a missing credit later
- Fleet child dispatch now persists the full specialist output inside the succeeded `TaskOperationRecord` claim, written in the same conditional state transition.
- A lost chain cache/link result now recovers that full output from the succeeded claim without re-dispatching and without using truncated `output_summary`.
- Fleet finalizer no longer credits an ambiguous nonunique audit join; it requires one exact audit id and now reports multi-row joins as `conflict`.
- Added tests for:
  - real Oracle positive, same-run and fresh-session replay
  - forged/raw verification flags
  - scope/ambiguity/shadow refusal
  - distinct outcomes and missing-credit recovery
  - forced SQLite stale-writer vs peer revocation CAS race
  - dirty, flushed, new, and deleted caller objects
  - full specialist output recovery without redispatch
  - ambiguous finalizer joins
