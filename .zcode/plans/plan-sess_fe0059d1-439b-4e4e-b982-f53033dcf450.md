# Plan: Three Gateway Features Inspired by Manifest Gap Analysis

Three independent but composable features that strengthen atom's LLM gateway layer. Each is self-contained; they integrate at different seams.

## Architecture context (from exploration)

The provider-call path runs through `BYOKHandler` (`core/llm/byok_handler.py`) with three entry points that each have their own try/except loop:
- `generate_response` (non-stream) — call at L1548, catch at L1656, `continue` at L1674
- `stream_completion` (stream) — call at L2779, catch at L2848, `continue` at L2870
- `generate_structured_response` — call at L2355, catch at L2424, **already has a classify-then-retry-once cascade** at L2476-2489 (the architectural precedent for autofix)

Key facts: all providers use the OpenAI SDK (`openai.AsyncOpenAI`/`OpenAI`) with different `base_url`s (L638-659). No per-provider param translation exists today. No status-code classification on the call path (bare `except Exception`). Cognitive tier classifier (`cognitive_tier_system.py:63`) already uses weighted regex patterns (`COMPLEXITY_PATTERNS` L73-109) — the template for the intent detector. Chat route (`chat_routes.py:194`) takes a Pydantic body, not a `fastapi.Request` — needs one added to read headers.

## Feature 1: Self-Healing Autofix (hybrid: rules first, LLM fallback)

**New file: `backend/core/llm/routing/request_healer.py`**

A `RequestHealer` class that inspects a provider error + the request payload and returns a patched payload (or `None` if unrepairable).

### Error classification
Introduce the first status-code-aware classification on the call path. Catch `openai.APIStatusError` (the SDK base for `BadRequestError`/`NotFoundError`/`UnprocessableEntityError`/`AuthenticationError`/`RateLimitError`), which carries `.status_code` and `.response`. Classify into:
- `REPAIRABLE_4XX` (400/404/422) → run healer
- `NON_REPAIRABLE_4XX` (401/403/429) → skip, fall back normally (auth/rate-limit issues aren't body problems)
- `5XX / transient` → skip, fall back

### Rule-based patches (instant, deterministic)
A registry of `HealingRule` objects, each with a `matches(error, payload, provider) -> bool` and `apply(payload) -> payload`. Initial rules:
1. **Param rename**: `max_tokens` → `max_output_tokens` (Gemini/Claude), `max_completion_tokens` (newer OpenAI reasoning models). Detect from error message keywords (`max_tokens`, `unexpected parameter`, `unknown argument`).
2. **Drop unsupported param**: remove `temperature` for o-series reasoning models (they reject it). Detect via model-name prefix `o1`/`o3`/`o4` + error mentioning `temperature`.
3. **Message format fix**: collapse multimodal `image_url` content to text-only when a provider rejects it (detected via `image`/`multimodal`/`unsupported content type` in error). Strip the image, keep text.
4. **Empty/oversize context**: if error mentions `context length`/`too long`, truncate messages to last N turns.
5. **Response format param**: drop `response_format={"type":"json_object"}` for providers that reject it (some OpenAI-compatible endpoints).

### LLM fallback healer (rules miss only)
When no rule matches but the error is still a repairable 4xx, optionally invoke a small/fast model (the cheapest available, e.g. `gpt-4o-mini`) with a constrained prompt: "Here is a failed API request and the provider's error. Return ONLY a JSON patch (RFC 6902 ops) that fixes the request body, or `{\"patch\": null}` if unrepairable." Apply the patch if it parses and only mutates safe keys (messages, max_tokens, temperature, response_format — never model/auth). Guard with a strict timeout (5s) and a one-attempt cap. Gated behind `ATOM_LLM_HEALER_ENABLED=true` (off by default; rule-based path is always on).

### Integration into byok_handler (3 call sites)
In each `except Exception as attempt_err` block, **before** the `continue`/fallback:
1. Check if `attempt_err` is a repairable 4xx (`isinstance(attempt_err, openai.APIStatusError) and attempt_err.status_code in {400,404,422}`).
2. If yes and no heal attempted yet for this provider, call `healer.heal(error, payload, provider)`.
3. If a patched payload comes back, rebuild the SDK call with the patched kwargs and retry **once**. Track `heal_attempted` flag (single heal per provider, mirroring the existing `cascade_attempted` pattern at L2489).
4. Log the original error + patch applied + retry outcome (both attempts recorded for observability, like Manifest's dual-row logging).
5. If the heal fails or the retry still errors, proceed to normal fallback (`continue`).

**Non-stream (L1656) and stream (L2848)** get the heal step. **Structured (L2424)** is left alone — it already has its own cascade; adding healing there would conflict.

### Observability
Add a lightweight `HealingLog` dataclass (original_error, provider, model, rule_applied_or_llm, patched_keys, retry_succeeded) collected per call and surfaced via the existing telemetry/EMA feedback path (`_record_outcome_feedback`) so the learning router knows a healed request succeeded/failed.

## Feature 2: Domain/Intent Classifier (core 6 categories)

**New file: `backend/core/llm/intent_detector.py`**

A `IntentDetector` class modeled directly on `CognitiveClassifier` (same weighted-regex + signal approach) but classifying *domain* instead of *complexity*.

### Categories (6)
`coding`, `data_analysis`, `web_browsing`, `creative_writing`, `reasoning`, `conversation`

### Signals (weighted)
1. **Keyword matching** — precompiled weighted regex per category, mirroring `COMPLEXITY_PATTERNS` structure. E.g. `coding`: `function|class|debug|refactor|api|sql|compile|stack trace` (+3 each match); `data_analysis`: `analyze|dataset|regression|correlation|statistics|chart|csv|dataframe` (+3); `web_browsing`: `search the web|latest news|current price|browse|url|website` (+3); `creative_writing`: `write a story|poem|creative|screenplay|novel|lyrics` (+3); `reasoning`: `prove|step by step|logic|derive|because|therefore|implies` (+3); `conversation`: `hello|thanks|how are you|chat` (+1, low weight).
2. **Structural signals** — code fences (``` → strong coding bias), URLs (web_browsing), long formal text (reasoning), via a `compute_signal_boosts` helper.
3. **Tool-prefix heuristics** — if the request carries agent tools, tool names starting with `browser_`/`web_` → web_browsing, `code_`/`editor_` → coding, `search_` → web_browsing (matches Manifest's approach; atom already has tool capability info via `required_capability`).
4. **Session stickiness** — if the last 3 turns in the same session classified as the same intent, add a small bias (+2) so an ambiguous turn doesn't flip routing. Session state lives in the orchestrator's session dict (`chat_orchestrator.py:1199`).

### Output
`IntentResult(category: Optional[str], confidence: float)` — category is `None` when no signal clears the activation threshold (mirrors Manifest's null-on-weak-signal). Confidence = `min(score / (threshold * 3), 1.0)`.

### Integration (tier nudge + predictor signal)
Two seams, both additive:
1. **Cognitive tier nudge**: In `CognitiveTierService.select_tier` (`cognitive_tier_service.py:76`), after the existing `user_tier_override` block, if intent is detected with confidence ≥ 0.5, nudge the tier: `coding`/`reasoning` → floor at VERSATILE, `conversation` → cap at STANDARD, `creative_writing`/`data_analysis` → floor at STANDARD. This refines model quality selection per intent without replacing the complexity signal.
2. **Learning-router cache key**: Add intent to the predictor cache key in `_rerank_with_learning` (`byok_handler.py:1796`) and `_score_candidates` (`learning_llm_router.py:950`): `f"{tenant}:{task}:{intent}"`. This lets per-model predictors learn that, e.g., DeepSeek wins coding intents even within the same task_type. Falls back gracefully to `intent=None` (no change from today) when detector returns null.
3. Add `intent: Optional[str]` to `RoutingResult` dataclass (`learning_llm_router.py:97`) for observability — zero downstream breakage (default `None`).

## Feature 3: Per-Request Header Overrides

**Modified files: `chat_routes.py`, `chat_orchestrator.py`, `llm_service.py`, `byok_handler.py`**

### Headers (3)
- `x-atom-tier` — force a cognitive tier (values: `micro|standard|versatile|heavy|complex`)
- `x-atom-model` — force a specific model id (bypasses auto-routing entirely)
- `x-atom-intent` — force an intent label (values: `coding|data_analysis|web_browsing|creative_writing|reasoning|conversation`)

### Threading
1. **Route handler** (`chat_routes.py:194`): Add `req: fastapi.Request` param (FastAPI injects by type alongside the Pydantic body). Parse the three headers into a `routing_overrides: dict`. Pass into `process_chat_message(..., routing_overrides=routing_overrides)`.
2. **Orchestrator** (`chat_orchestrator.py`): Accept `routing_overrides` kwarg, thread into the `generate_completion` call.
3. **LLMService.generate_completion** (`llm_service.py:257`): Accept `routing_overrides`, unpack: `model_override = overrides.get("model")` → if set, pass as the `model` arg (already short-circuits auto at L841). `tier_override = overrides.get("tier")` → pass as `cognitive_tier` (already plumbed at L667). `intent_override = overrides.get("intent")` → new param.
4. **BYOKHandler.generate_response** (`byok_handler.py:1340`): Accept `model_override`/`tier_override`/`intent_override` kwargs. `model_override` skips routing, uses that model directly. `tier_override` skips the classifier, uses that tier. `intent_override` skips the detector, uses that intent. Each override is optional and independent.

### Validation
Validate header values at parse time (route handler): tier must be a valid `CognitiveTier` enum value, intent must be a valid category, model must exist in the registry. Invalid values are logged-and-ignored (not 400'd) so a bad header never breaks a chat request — fail open to default routing.

### Security
Header overrides are a privileged control (can force expensive models). Gate behind the existing `current_user` auth — no additional role check needed since the route is already authenticated. Document that these are advisory (the budget enforcement at L1376 still blocks overrides that exceed budget).

## Build order

1. **Intent detector** (Feature 2) first — it's the most isolated (new module + two additive integrations) and unblocks the header override's `x-atom-intent`.
2. **Header overrides** (Feature 3) second — depends on intent detector existing for the `x-atom-intent` path; otherwise just threading kwargs.
3. **Self-healing autofix** (Feature 1) last — largest and most invasive (touches 2 call sites in byok_handler, adds error classification, rule registry, optional LLM path). Done last so the first two can be validated independently.

Each feature is committed and pushed separately so CI validates incrementally.
