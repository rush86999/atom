## Goal
Make the canvas UI for Excel (.xlsx), Word (.docx) and PowerPoint (.pptx) files support **user editing** side-by-side with **agent editing**, with both directions syncing through the real file on disk.

## Current state (from exploration)
- Backend is mostly ready: `/api/v1/office/*` endpoints read/write real files, `OfficeSyncService.broadcast_file_update` re-renders the file to HTML and broadcasts `component: "office_preview"` over WS — but the **frontend has no handler for `office_preview`**, so it falls through to the raw-JSON default.
- `sync_canvas_to_file` supports xlsx cell writes and a destructive docx whole-document overwrite; **pptx sync is not supported**.
- Frontend sheet/document canvases edit in-memory JSON/markdown, never the real file; pptx isn't rendered at all.

## Plan

### 1. Backend — structured payloads + pptx/docx sync support
**`backend/core/office_service.py`**
- Extend `PowerPointManager.modify_slides` with new actions:
  - `set_shape_text`: options `{slide_index, shape_name, text}` — sets text on an existing shape's text frame (preserves shape/layout).
  - `set_slide_title`: options `{slide_index, title}`.

**`backend/core/office_sync_service.py`**
- `sync_canvas_to_file`: add edit types:
  - `paragraph` (docx): data `{index, text}` — open existing doc with python-docx, set `doc.paragraphs[index].text` (preserves styles/runs better than the current full-overwrite). Keep `document` type for full-content writes.
  - `slide` (pptx): data `{slide_index, shape_name, text}` — delegate to the new `set_shape_text` action.
- `broadcast_file_update`: include structured data in the WS payload alongside HTML so the frontend can rebuild editors:
  - xlsx: sheet name + cell values matrix (from openpyxl)
  - docx: paragraph list `[{index, text}]`
  - pptx: slides from `PowerPointManager.read_slides`
  - Payload becomes `{html, file_path, file_type, structured: {...}}`; canvas_type for pptx set to `docs` (or new `slides` value).

**`backend/api/office_routes.py`**
- Add `GET /api/v1/office/render?file_path=` returning `{html, file_type, structured}` so the frontend can hydrate an office canvas on open (reuses `broadcast_file_update`'s render logic; extracted into a shared helper).

### 2. Frontend — shared `OfficeFileCanvas` component
**New `frontend-nextjs/components/canvas/OfficeFileCanvas.tsx`** — one component, three modes by `file_type`:
- **xlsx**: editable grid (reuse the existing sheet `<table>`+`<input>` pattern) fed from `structured.cells`; on cell blur/commit → `POST /api/v1/office/sync-update` with `edit_type: "cell"`; "Add Row" → existing `/excel/insert-rows`.
- **docx**: paragraph list rendered as editable blocks (textarea per paragraph, keeps the existing aesthetic); commit per-paragraph → `sync-update` with `edit_type: "paragraph"`; a "whole document" Monaco/markdown fallback stays for the legacy in-memory document canvas.
- **pptx**: slide cards (from `structured.slides`) with editable title/content fields per shape → `sync-update` with `edit_type: "slide"`.
- Shows `html` preview toggle (sanitized via existing `renderMarkdownSafe`-style sanitization — add an HTML sanitizer pass since office HTML is backend-generated but should still be sanitized before `dangerouslySetInnerHTML`).
- Handles incoming WS `canvas:update` (component `office_preview`): merges new state **unless the user has unsaved edits in the focused field** (guard with a `dirtyRef`), and shows an "Agent updated this file" toast/badge so co-editing is visible.

**`CanvasPanel.tsx` and `chat/canvas-host.tsx`**
- Add `office_preview` to the component union + a case in `CanvasContent` that renders `<OfficeFileCanvas>` with `data.file_path` / `data.structured` / `data.html`.
- On open, if `structured` is missing, hydrate via `GET /api/v1/office/render`.
- Save button routes to `/api/v1/office/sync-update` instead of `/api/artifacts` for office files.

### 3. Round-trip / co-edit flow
- User edit → `sync-update` → backend writes file → `broadcast_file_update` → WS `canvas:update` → all canvas instances (and the chat one) re-render with fresh structured data → memory ingestion already handled by backend.
- Agent edit (existing tools `write_excel_cell`, `modify_word_document`, `modify_pptx_slides`) → `broadcast_file_update` → same WS path → user's canvas refreshes (skipped while user has a dirty field).

### 4. Tests & verification
- Backend: pytest for new edit types (`paragraph`, `slide`) in the existing office test suite style (`backend/tests/`), plus `/render` endpoint test.
- Frontend: `npm --prefix frontend-nextjs run build`; manual/browser check of the three file types editing + agent-broadcast refresh if feasible.
