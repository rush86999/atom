## Stage Router + Weighted-Random Split — shadow-mode v1 (agent path)

### Goal
Add (1) a **stage router** (proactive tier selection from conversation/tool signals) and (2) a **weighted-random traffic split** (calibration harness), both running in **shadow mode** on the agent path, plus a calibration data store so per-workload thresholds get tuned from real data before going live. Bundles the escalation↔stage handoff notes (#3).

### Locked design decisions
- **Pipeline**: agent path only — `CognitiveTierService` / `generate_with_cognitive_tier`. Gateway path is a documented fast-follow.
- **Signal source**: the inbound `messages` array (re-sent every request). **No** `GatewayRequestLog`-body dependency — sidesteps the schema gap (no session grouping; bodies off-by-default/redacted).
- **Shadow logging**: dedicated `StageRouterShadowLog` table, written from the one shared seam `_record_outcome_feedback` (byok_handler.py:2241, every attempt funnels through it).
- **Home**: `CognitiveTierService` — next to `escalation_manager` (stage = proactive complement to reactive escalation).

### Signals (messages-derived, Switchyard-aligned)
- **severity** — count of `tool` role messages with error/`is_error` content in the window → tanh-squashed
- **spinning** — repeated identical `tool_call.name` / high tool-call density with no assistant text
- **exploring** — read-tool count ≫ write-tool count in window
- **recent_production_intensity** — write-tool count in window

Each signal `tanh`-squashed to `[0,1]`; a single signal scores ~0.46; a second corroborating signal crosses 0.5. Hard override: critical severity → capable tier regardless.

### `StageRouterShadowLog` schema
`id, workspace_id, tenant_id, workload_type, agent_type, decision_id, signals_json, stage_target_tier, stage_confidence, stage_axis, actual_tier, actual_model, actual_provider, success, quality, cost_usd, latency_ms, created_at` + indexes on `(workspace_id, created_at)` and `workload_type`; 30-day sweep (mirrors `GatewayRequestLog` retention).

### Wire points
1. **`select_tier`** (cognitive_tier_service.py:76) — add `messages: Optional[List[dict]] = None`; after the classified tier is computed, if `stage_router_enabled()`: `decide(messages, classified_tier)` → shadow: stash on a per-request carrier + log `[StageRouter]`; live (`stage_router_live()`): override `classified_tier`.
2. **byok_handler.py:2546** — pass `messages` (available in `generate_with_cognitive_tier`) into `select_tier`.
3. **`_record_outcome_feedback`** (byok_handler.py:2241) — after the learning-router block, write a `StageRouterShadowLog` row if a shadow decision was stashed for this request.
4. **`traffic_split.assign_arm`** — in `generate_with_cognitive_tier`, when `traffic_split_enabled()`, pick a weighted-random arm from the ranked options for calibration exposure (logged, not yet overriding unless a future flag says so).

### Calibration loop
`scripts/calibrate_stage_router.py` — aggregates `StageRouterShadowLog` grouped by `workload_type × signal-bucket`, compares weak-arm vs strong-arm cost/quality when the stage router said *efficient* vs *capable*, recommends per-workload `confidence_threshold` + picker. Output: a JSON config the `StageConfig` can load.
