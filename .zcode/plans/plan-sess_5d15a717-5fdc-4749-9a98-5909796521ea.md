# Plan: Fix the two Reddit critiques — Resumability + Spend Halting

The loops critique already passes (hard `max_steps` everywhere + DAG cycle rejection). This plan addresses the two that fail: **crash resumability** and **spend that doesn't halt**.

User decisions (confirmed): **reconcile-only** resumability (mark crashed, no auto-restart), **per-tenant in-loop** budget halting, default mode **`soft_stop`**.

---

## Part A — Resumability: crash-recovery sweep (reconcile-only)

**Problem:** A process crash mid-run leaves `WorkflowExecution` / `AgentExecution` rows stuck in `RUNNING` forever — invisible to failure dashboards, never retried, never failed. The dead `core/startup_tasks.py` import is silently swallowed.

**Fix:** Add a startup reconciliation sweep that finds orphaned `RUNNING` rows and marks them as crashed/failed, so they become visible and retryable. Safe — no double-execution risk.

### A1. New module: `backend/core/execution_recovery.py`
- `async def reconcile_orphaned_executions() -> dict` — the sweep.
- Queries all `WorkflowExecution` rows with `status == "RUNNING"` and all `AgentExecution` rows with `status == "running"`.
- For each: marks `WorkflowExecution.status = "FAILED"`, appends `{"crashed": true, "recovered_at": now}` to a `recovery` field; `AgentExecution.status = "failed"`, sets `error_message = "Process restarted while execution was running (crashed)"`, sets `ended_at`.
- **Idempotent + bounded:** runs once per startup, only touches rows in the running state, logs a count.
- Gated by env `ATOM_EXECUTION_RECOVERY_ENABLED` (default `true`) so it can be disabled.
- Returns a summary dict `{"workflow_recovered": N, "agent_recovered": M}`.

### A2. Wire into startup (`main_api_app.py` lifespan, ~line 518)
- Replace the dead `from core.startup_tasks import run_startup_maintenance` block with a real call to `reconcile_orphaned_executions()`. Keep it wrapped in try/except (existing pattern) but log the summary instead of silently swallowing.
- Only runs when not in test mode (gated by the existing `is_test_mode` check already wrapping this section).

### A3. Add `crashed`/`interrupted` to the status vocabulary
- The `WorkflowExecution` status enum is `PENDING/RUNNING/COMPLETED/FAILED/PAUSED`. Marking crashed rows as `FAILED` (with a `recovery` JSON marker) reuses an existing status that dashboards already key off — no schema/enum change needed. Same for `AgentExecution` (`failed`).
- This avoids introducing a new status value that existing queries wouldn't recognize.

> **Why not auto-resume:** the resume-skip logic already exists (`workflow_engine.py:614`), but re-entering a crashed run risks double-firing side effects (emails sent, cards charged) from a partially-completed step. Reconcile-only makes the problem *visible and safe* first; auto-resume can layer on later once steps declare idempotency.

## Part B — Spend halting: make the budget setting actually stop runs

**Problem:** Budget defaults to `alert_only` (never blocks); `check_budget_before_action` is only called before *tools*, not before the expensive LLM call; a denial doesn't break the loop; `enforce_budget` (the cancellation path) has zero callers.

**Fix:** Wire the budget check before each LLM call in the agent loop; break cleanly when denied in `hard_stop`; change the default mode to `soft_stop`; expose the setting via a tenant admin API.

### B1. Wire pre-LLM budget gate in `atom_meta_agent.py` (the main agent loop)
- At the top of each iteration, immediately before `_react_step` (~line 678), add a budget check:
  ```python
  # Spend gate: check BEFORE the expensive LLM call (not just before tools).
  budget = await self._check_budget_before_react(tenant_id, execution_id)
  if not budget.get("allowed"):
      final_answer = f"Budget limit reached: {budget.get('reason')}"
      status = "budget_exceeded"
      break
  ```
- `_check_budget_before_react` is a thin new method that calls `BudgetEnforcementService.check_budget_before_action(tenant_id, "atom_main", "llm_react_step")` and returns the dict. Fail-open on exception (existing convention) but logs.
- This means `hard_stop` now breaks the loop at the next iteration's LLM call (clean exit mirroring the `max_steps` path at line 894-902), and `soft_stop` blocks *new* runs while letting the active one finish (since `_has_active_episodes` is true mid-run).

### B2. Wire the same gate in `generic_agent.py`
- Mirror B1 in the generic agent loop (`generic_agent.py` ~line 147, before its `_react_step`). Same pattern: check → break with `status="budget_exceeded"` if denied.

### B3. Map `budget_exceeded` to a valid status
- Like `max_steps` → `timeout` mapping (line 894-902), `budget_exceeded` is not in `ExecutionStatus`. Map it to `"failed"` for persistence (so failure dashboards catch it) but keep the in-memory `status="budget_exceeded"` for the response/observation so callers can distinguish. Set `AgentExecution.error_message = "Budget exceeded"`.

### B4. Change default enforcement mode to `soft_stop`
- In `budget_enforcement_service.py:_get_enforcement_mode` (~line 373, 381, 388), change the three `ALERT_ONLY` defaults/fallbacks to `SOFT_STOP`. This makes budget enforcement *active by default* — new episodes are blocked once over budget, active ones complete. Existing tenants with an explicit `alert_only` setting keep their setting; only the *unset* default changes.

### B5. Tenant admin API for the budget setting
- New routes in an existing admin/tenant router (find the tenant-settings router during impl): 
  - `GET /api/tenants/{tenant_id}/budget` → returns `{limit_usd, enforcement_mode, current_spend_usd, utilization_percent}`.
  - `PUT /api/tenants/{tenant_id}/budget` → sets `Tenant.budget_limit_usd` and `TenantSetting['billing']['enforcement']['mode']`. Validates mode ∈ `BudgetEnforcementMode.ALL`. Admin-only.
- Reuses the existing `TenantSetting` storage (`_get_enforcement_mode` already reads from there) — no schema change.

- Already-`COMPLETED`/`FAILED` rows are untouched (idempotency).

### C2. Extend `backend/tests/test_budget_enforcement_service.py`
- Default mode is now `SOFT_STOP` (update the existing default-mode test).
- New: a run over budget with `hard_stop` → `check_budget_before_action` returns `allowed: False`.
- New: a run over budget with `soft_stop` + active episode → `allowed: True` (finishes); without active episode → `allowed: False` (blocks new).

### C3. `backend/tests/test_agent_budget_gate.py`
- Unit-test `_check_budget_before_react`: when `allowed: False` + `hard_stop`, the loop breaks with `status="budget_exceeded"` and a budget final answer. Use a stubbed `BudgetEnforcementService` so no real spend aggregation runs.
- Confirm fail-open on exception (loop continues).

## Out of scope
- Auto-resume from checkpoint (reconcile-only is the safe first step; auto-resume needs per-step idempotency declarations).
- The `SpendAggregationWorker` background cancellation path (`enforce_budget` caller) — the in-loop gate covers the dominant cost (LLM calls); the worker is a separate, larger follow-up.
- Linearizing the fragmented alembic chain (separate effort, already worked around by `create_all`).

## Verification bar
- After this: a crashed run is marked FAILED and visible (no more ghost `RUNNING` rows). A run over budget in `hard_stop` halts at the next LLM call with `budget_exceeded`; `soft_stop` (new default) blocks new runs over budget while letting active ones finish. The setting is queryable/settable via tenant admin API. The reddit critic's two filters now both pass: resumability → crash is recovered (reconciled, not orphaned); spend → actually halts.
